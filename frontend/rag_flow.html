Metadata RAG Flow

How the clinical agent dynamically reflective schemas to save cost and latency

The Retrieval & Reflection Pipeline

1

Natural Language Input

The user submits a question like "Show me patients and their total charges". The agent captures this question and invokes the RAG pipeline prior to generating SQL queries.

2

TF-IDF & Cosine Similarity Matcher

The MetadataRAG system tokenizes the query and compares it against pre-indexed metadata representing table names, column descriptions, and logical semantic rules. Tables are ranked by relevance score.

3

Relational Semantic Expansion

To ensure queries compiles successfully, the RAG engine performs relational graph-boosting. If a related child table (e.g. medications or vitals) scores highly, its primary joining table (e.g. patients) is automatically pulled into the reflected context.

4

Targeted Schema Projection

Only the database schemas (DDL definitions) for the matched tables are retrieved from the catalog and sent to the SQL-generation prompt. Unrelated tables (e.g. lab_orders, vitals) are completely filtered out.

Cost & Token Comparison

Traditional Approach

  • Sends entire database DDL schema.
  • Prompts scale linearly: 11,000+ tokens.
  • High LLM parsing cost and increased latency.

Metadata RAG Approach

  • Sends only relevant table DDL schemas.
  • Prompts remain compact: ~3,300 tokens.
  • Saves ~70% in token costs per query!
